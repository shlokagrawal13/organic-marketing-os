# Browser-local workspace settings draft recovery (UX-01I)

Unsaved workspace name and timezone edits are backed up in this browser under the signed-in user and workspace IDs. The backup contains the prior saved fields, saved revision and uncertain/conflict flags. It stays on the device; there is no upload or background settings PATCH. The editor explains this storage in the settings panel. A successful acknowledged save, explicit discard, confirmed reload or successful sign-out removes the account's backup. A failed sign-out retains it.

After a reload or browser restart, the editor first reads current server settings. It offers Recover or Discard only to the same signed-in user and workspace. It does not silently put the backup into the form, and the form stays locked while a backup awaits a choice. Recovery performs a fresh authorized GET. A matching confirmed revision restores an unsaved proposal. A stale, conflicted or unconfirmed backup enters the existing field-by-field revision review; Save remains disabled until review is accepted. A failed GET leaves the backup available. The existing atomic server revision, role, audit and manual save checks remain authoritative.

Browser storage can be disabled, cleared or evicted, so the existing manual JSON export/import remains available. This is local draft recovery, not a server backup, automatic server save, cross-device sync, encrypted storage or production durability. Tests cover reload recovery without writes, one acknowledged manual save, stale revision review, signed-in user separation, explicit discard, sign-out cleanup and all earlier settings behavior in an owned fixture. Full CI still verifies fixtures and does not deploy.
