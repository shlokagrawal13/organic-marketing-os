# Chinese, Japanese and Korean render text

EDITOR-01V adds a saved `cjkLanguage` option: `zh-Hans`, `zh-Hant`, `ja` or `ko`. Choose it when burning Chinese, Japanese or Korean titles/caption cues into a video. The selection is saved with the render snapshot and displayed in the preview; editing another render does not change that snapshot. Shared Han characters do not identify a language, so omission is rejected before a render job is created. Japanese kana requires `ja`; Hangul requires `ko`. Use separate exports for different CJK languages; per-overlay language selection is not implemented.

An administrator must independently enable each script present in effective rendered text using `RENDER_HAN_ENABLED`, `RENDER_HIRAGANA_ENABLED`, `RENDER_KATAKANA_ENABLED` and `RENDER_HANGUL_ENABLED`. All four default to false. Both API and render worker need matching flags and trusted covering fonts. Choose suitable regional fonts through `RENDER_FONT_PATH` and `RENDER_FONT_FALLBACK_PATHS`. The existing complete-grapheme fallback selection, derived glyph checks and controlled Fontkit outline pipeline remain in place. Mixed enabled Indic/SEA scripts and Latin/Greek/Cyrillic can share an overlay; Arabic/Hebrew remain separate overlays. Runtime shaping does not download fonts or invoke HarfBuzz/Python.

Only administrator supplied single TTF/OTF faces from 12 bytes to 16 MiB are accepted. Collections, web-font containers, truncated files and uncovered original or derived glyphs fail before storage/cache/media work. The static Noto Sans CJK Sans 2.004 test faces are pinned by commit, length and SHA-256 in `scripts/install_test_cjk_fonts.py` / `tests/fixtures/cjk-fonts.json`; they are test fixtures, not bundled runtime assets or production typography guarantees.

Fontkit receives explicit OpenType language tags for CJK script runs, preserving adjacent common punctuation (including Japanese prolonged-sound marks) in context. NFC is used for CJK shaping/measurement only; stored text and Unicode SRT retain the original input. The effective cue override and captions-off rules are unchanged. Saved language, font bytes, layout settings and shaping runtime participate in scene identity; unchanged renders reuse valid cache entries, while language or font changes rebuild them. The new scene cache revision invalidates prior scenes.

Wrapping uses pinned `linebreak` 1.1.0's Unicode 13 UAX #14 baseline, intersected with complete graphemes, strict Japanese non-starters/opening brackets, Korean word protection and existing ICU dictionary protection for mixed SEA/Tibetan words. This is conservative bounded acceptance, not universal current-Unicode conformance. Unbreakable units reduce the font size or fail at the existing readable minimum; no arbitrary CJK emergency splitting is used.

CJK variation sequences, broader/variable font acceptance, additional line-break language tailoring, mixed CJK language exports and physical-device readability remain open. Preserve unsupported text and use an image overlay where appropriate. Existing Indic/SEA joiner and word-break-control gaps remain open. See `docs/qa/cjk-batch-evidence.json` for independent shaping, boundary, decoded-frame and regression receipts once this increment closes. EDITOR-01 remains Partial; deployment/live/master acceptance is separate.

The CI test profile installs explicit HarfBuzz/ICU oracle libraries and the hash-pinned CJK fonts before builds/tests. Runtime application dependencies do not include those Python oracles. Local evidence keeps newer and Ubuntu CI legacy font sets separate; clean full/production installs retain the exact guarded Fontkit bytes.
