# Pre-target historical versions and physical application recovery

RECOVERY-01I adds a seventeenth phase to the disposable Compose verifier. The original sixteen phases and all existing assertions remain. The phase calls the existing physical PostgreSQL runner with three optional fixture hooks; its standalone CLI still runs the original database-only acceptance. PostgreSQL retains no network, ports or persistent volumes. Windows uses Docker Desktop's Linux-engine named pipe; Linux retains the Unix socket.

The ordered experiment is:

1. Build the unchanged 24-migration application schema and 19 synthetic rows in 11 of 37 tables, take and verify the physical base backup, and save the approved target revision.
2. Read the application snapshot before the named restore point. Create the synthetic Asset's original bytes in the separate owned/versioned MinIO bucket. Capture the actual version ID, metadata, byte hash, typed reference inventory, whole application-snapshot digest, physical fixture identity, base-manifest digest and target name. Await successful capture and explicit version readback before creating the PostgreSQL restore point.
3. Save the native target LSN in a separate receipt that fingerprints the unchanged pre-target manifest. Later SQL changes delete the Asset reference; later S3 operations overwrite its bytes and add a delete marker.
4. Retain the corrupt-base, missing-WAL, unreachable-target, clean-retry, exact-row/column-metadata, promotion, source-preservation, immutable-credit, foreign-key, idempotency and tenant/revision assertions. Independently query the recovered application snapshot before restored-write tests modify it. Compare the entire snapshot, typed references and exact version manifest with the pre-target evidence, then read the explicit historical version through S3.
5. Reject changed target/base/capture receipts, altered snapshots/inventories, current-version substitution and a nonexistent version before the harness readiness callback. Anonymous historical reads remain denied. Permanently delete the original version, require native 404 and deny a second callback; preserve the saved manifest and later version. Cleanup validates the owner tag and exact version/delete-marker set before deleting only those versions and proving the bucket absent.

The native populated fixture binds one Asset reference/version. Other supported reference fields have unit coverage; this increment does not populate every application object-bearing table in the physical experiment. The full source application's original six private objects and database baseline must remain unchanged afterward, with all five writers still stopped. G/H's historical external-effect reconciliation and fresh-Redis recovery phases remain required independently.

This is a physical application-snapshot/private-version binding experiment with a harness readiness probe. It does not serve the application from the historical bucket, reconstruct Redis against the physical cluster, establish complete real-provider effect inventories, or authorize production recovery. Coordinated application/Redis/external-effect acceptance, durable retention, remote backups, encryption/access policies, RPO/RTO, deployed/live and full-master acceptance remain open. CI verifies fixtures and does not deploy. A source ZIP is not a native database/media backup.

The Windows drill exposed a false-ready observation: pg_ctl returned zero while the native log recorded target-not-reached FATAL and shutdown. PostgreSQL documents that pg_ctl determines readiness from the PID file ([PostgreSQL17 pg_ctl](https://www.postgresql.org/docs/17/app-pg-ctl.html)). Negative cases now run PostgreSQL in the foreground under a bounded supervisor and require its actual exit code1, the native FATAL and rejected SQL connections. A timeout is not accepted. Successful retry still uses pg_ctl and requires code0 plus the existing SQL/promotion/write checks. Exactly one explicit native exit-status marker is required; missing or ambiguous markers fail closed. Initial failures remain retained; the precise timing cause of pg_ctl's zero return is not claimed.

Evidence: docs/qa/recovery01i-evidence.json and the exact final-commit external receipt paired with the source ZIP. H's final receipt is retained in docs/qa/recovery01h-final-ci-receipt.json.
