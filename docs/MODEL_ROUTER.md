# Model router

`packages/core/ai.ts` centralizes compatible chat-completions routing and output contracts. Each server-side provider declares its model, task capabilities, quality tier, allowed plans, priority and optional token prices. Provider configuration is not a live quality or connectivity check; operators must not label an unbenchmarked model premium.

Each route applies task complexity, required capabilities, minimum quality, active workspace plan, shared health and an optional maximum estimated dollar cost before any call. Strategy and scene tasks require premium quality; content requires standard quality. A configured dollar cap requires both token rates, so unknown-cost routes are rejected instead of treated as free. Priority preserves explicit primary/fallback order; health and cost are retained in route evidence.

Provider health is stored in Redis by the text worker, so cooldown, attempts, failures and rolling latency are shared across worker processes. Definitive HTTP rejection may move to an eligible comparable fallback. A transport failure, timeout after request dispatch, empty/invalid successful response or schema-invalid output may already be billable and therefore stops without a second call. Invalid task output does not cool the provider for unrelated work. Rate limits, provider outages and authentication failures use bounded cooldowns. Abort never starts fallback.

Abort stops the request and suppresses fallback. A usage-database write failure also stops the job; it cannot trigger another potentially paid provider call. Worker ownership, 1-second heartbeat and a 210-second total deadline prevent an obsolete execution from committing success. A lost/stale RUNNING job is failed with an interrupted-call warning, never automatically regenerated. This prevents intentional replay but cannot undo an already accepted provider charge.

New jobs capture the brand revision, profile and Creative DNA when queued. A repeated organization/requestKey with the same task/input returns the existing job; changed task/input returns 409. Later brand edits do not alter a saved job's context. Jobs created before migration 6 have no snapshot and use the then-current brand if still queued. A scene task requires a valid scene; other tasks reject a scene field.

Usage records contain provider/model, tokens where available, latency, outcome, retry index, quality, failure code, provider request ID, unknown-outcome state, route metadata and estimated cost when rates are configured. Null means unknown, not zero. Estimated cost is not an invoice; failed, invalid or interrupted requests can incur charges. Product-credit reservations and settlement are implemented as described in BILLING.md; they do not guarantee a zero provider invoice. Pre-request accounting-hook failures also prevent any provider call.
