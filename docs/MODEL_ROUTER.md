# Model router

`packages/core/ai.ts` centralizes compatible chat-completions routing and output contracts. Primary/fallback configurations each have a server-side URL, key, model and optional token prices. Provider configuration is not a live quality or connectivity check.

Each request asks for a JSON object and has a 90-second provider timeout plus a bounded 1 MiB response body. Strategy, draft and scene output must pass Zod validation. Returned token counts must be nonnegative safe integers. Eligible transport/HTTP/JSON/schema failures record a failed attempt and may use the configured fallback. Transport/HTTP/envelope failures cool a provider down for 30 seconds in that worker process. Valid provider envelopes containing task-specific malformed JSON or invalid schema output are rejected without disabling the provider for other jobs. Aborted job requests do not poison provider health.

Abort stops the request and suppresses fallback. A usage-database write failure also stops the job; it cannot trigger another potentially paid provider call. Worker ownership, 1-second heartbeat and a 210-second total deadline prevent an obsolete execution from committing success. A lost/stale RUNNING job is failed with an interrupted-call warning, never automatically regenerated. This prevents intentional replay but cannot undo an already accepted provider charge.

New jobs capture the brand revision, profile and Creative DNA when queued. A repeated organization/requestKey with the same task/input returns the existing job; changed task/input returns 409. Later brand edits do not alter a saved job's context. Jobs created before migration 6 have no snapshot and use the then-current brand if still queued. A scene task requires a valid scene; other tasks reject a scene field.

Usage records contain provider/model, tokens where available, latency, outcome and estimated cost when rates are configured. Null means unknown, not zero. Estimated cost is not an invoice; failed, invalid or interrupted requests can incur charges. Product-credit reservations and settlement are implemented as described in BILLING.md; they do not guarantee a zero provider invoice. Pre-request accounting-hook failures also prevent any provider call.

Pending: task/plan/quality-aware selection, shared provider health, provider dollar caps, plan policy and payment refund reconciliation, generated image/video/voice/embedding adapters, live model quality and rate benchmarks, and provider-native unknown-outcome reconciliation. Operators must choose a comparable fallback; equivalence is not asserted by the router.
