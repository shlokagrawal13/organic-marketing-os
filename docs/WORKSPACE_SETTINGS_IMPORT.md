# Workspace settings draft import (UX-01H)

The settings editor can import its existing `workspace-settings-local.json` export after a confirmed reload or browser restart. The browser parses a nonempty JSON file under 64 KB locally and requires an exact workspace ID, a nonnegative safe saved revision, string name/timezone fields and the export's uncertainty/conflict flags. Imported values are projected to the two editable fields; extra JSON properties cannot enter a settings PATCH. An existing local proposal is replaced only after explicit confirmation. Malformed and foreign-workspace files leave the current draft untouched. The file itself is never uploaded.

Import performs a fresh tenant-guarded GET before adopting the file. If its saved revision equals the server revision and the export had no uncertain/conflict flag, the recovered proposal remains unsaved until the user chooses Save workspace. A stale revision or prior uncertain/conflict flag shows the existing three-way review with the imported baseline, current server values and recovered draft. The user selects fields, accepts the reviewed revision without a write, then saves manually. A new concurrent server write still receives 409 through the existing atomic API guard. A failed GET leaves the current draft unchanged.

This restores a manually exported file; it is not automatic browser-crash persistence, a server backup or an automatic merge. Tests exercise same-revision recovery, rejected foreign/malformed files, confirmation before replacement, extra-field projection, stale and uncertain exports, absence of import writes, and the final tenant-bound manual save. All 25 migrations, 24 Compose recovery phases and production API guards remain unchanged. CI verifies isolated fixtures and does not deploy.
