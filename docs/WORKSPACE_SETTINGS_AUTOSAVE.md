# Opt-in workspace settings autosave (UX-01J)

Workspace name and timezone still use manual Save by default. An OWNER or ADMIN may enable autosave for the current settings-editor session. After two seconds without edits, a valid dirty form sends one PATCH carrying the last acknowledged `settingsRevision`. The existing tenant, role, atomic revision and audit checks remain authoritative. An acknowledged response updates the saved baseline and clears the browser-local draft backup; a later edit can start another debounce. The checkbox resets when the editor is reopened.

The editor serializes manual and automatic writes with the same in-flight guard. Inputs and navigation are disabled during a request, so a second write cannot overtake the acknowledgement. Invalid name or timezone values do not schedule an automatic request. Any failed request turns autosave off. A conflict retains the draft and requires explicit field review; an uncertain outcome remains blocked and is never retried automatically. Importing or recovering a local draft, and reloading server settings, also turn autosave off so those actions cannot silently write restored values. Manual Save remains available when the existing revision and uncertainty guards permit it.

Browser tests verify default manual mode, opt-in debounce and two exact revisions/audit entries, switching autosave off, concurrent 409 with zero automatic replay and explicit manual review, and a committed response lost after the actual write. All prior settings assertions remain. This is not cross-device synchronization or automatic merge. CI verifies owned fixtures and does not deploy.
